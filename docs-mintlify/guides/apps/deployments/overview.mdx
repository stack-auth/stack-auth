The Deployments app lets you host your app's frontends and APIs alongside your Hexclave backend. You configure each service once (framework, build commands, env vars) and deploy it with a single CLI command; the source is uploaded and built remotely. Deployments is currently in beta.

## Set up a service

Enable the Deployments app in the dashboard, then add a service on the board and configure its build settings and variables there. That's all you need — `hexclave deploy <service>` run from your app's directory uses the configuration stored in Hexclave.

Alternatively, keep the configuration in your repo by defining the service in a `hexclave.config.ts` under `deployments.services` (when present, it governs the deploy and is upserted back to Hexclave — config as code):

```ts title="hexclave.config.ts"
import type { HexclaveConfig } from "@hexclave/js/config"; // replace `js` with the correct framework SDK package

export const config: HexclaveConfig = {
  deployments: {
    services: {
      web: {
        type: "vercel",
        rootDirectory: "./",          // the local source directory to upload
        framework: "nextjs",
        installCommand: "pnpm install",
        buildCommand: "pnpm build",
        outputDirectory: ".next",
        env: {
          "MY_ENV_VAR": { value: "true" },
          "DATABASE_CONNECTION_STRING": { type: "secret", key: "db_connection" },
          "NEXT_PUBLIC_HEXCLAVE_PROJECT_ID": { type: "connection", value: "hexclave.projectId" },
        },
      },
    },
  },
};
```

`type: "vercel"` is required; the build fields are optional — omit what the platform can auto-detect.

## Env vars

Each entry under `env` is one of three kinds:

- **Value** — `{ value: "..." }`: a literal value, committed to the config as-is.
- **Secret** — `{ type: "secret", key: "db_connection" }`: only the secret's *name* goes in the config. Its value is passed at deploy time with `--secret db_connection=...`, pushed to the deployment target as an encrypted env var, and never stored by Hexclave — so this file is always safe to commit.
- **Connection** — `{ type: "connection", value: "hexclave.projectId" }`: a typed pointer to another service's output, resolved by Hexclave at deploy time. The managed `hexclave` service exposes `projectId`, `apiUrl`, `jwksUrl`, `publishableClientKey`, and `secretServerKey`; other services expose `url` and `previewUrl`.

Connections are a distinct type on purpose: a plain value is always pushed verbatim, so a literal that happens to contain something like `{...}` is never misread as a reference.

## Deploy

From the directory containing your config file:

```sh title="Terminal"
hexclave deploy web --secret db_connection="$DATABASE_URL"
```

The CLI packages the service's root directory (respecting `.gitignore` and `.vercelignore`, and always excluding `node_modules` and `.git`), uploads it, and starts a remote build. Without a config file, the configuration stored in Hexclave governs the deploy, with the root directory resolved against the current directory. It always deploys to production, never prompts, and exits as soon as the build is queued, printing the run id. Follow the build in the dashboard's Deployments tab.

Every secret defined in the service's env must be passed via `--secret` on every deploy — a missing (or misspelled) one fails the deploy before anything is uploaded.

Options: `--config <path>` (default: auto-discover `hexclave.config.ts` in the current directory, dashboard configuration otherwise), `--cloud-project-id <id>` (default: the `HEXCLAVE_PROJECT_ID` env var), and `--secret KEY=VALUE` (repeatable, see above).

## Deploying from GitHub Actions

In CI, authenticate with an API key instead of `hexclave login`: set `HEXCLAVE_PROJECT_ID` and `HEXCLAVE_SECRET_SERVER_KEY` (from your project's API Keys page) as repository secrets.

```yaml title=".github/workflows/deploy.yml"
- run: npm i -g @hexclave/cli
- run: hexclave deploy web --secret db_connection="$DATABASE_URL"
  env:
    HEXCLAVE_PROJECT_ID: ${{ secrets.HEXCLAVE_PROJECT_ID }}
    HEXCLAVE_SECRET_SERVER_KEY: ${{ secrets.HEXCLAVE_SECRET_SERVER_KEY }}
    DATABASE_URL: ${{ secrets.DATABASE_URL }}
```

`hexclave deploy` waits while the source is uploaded and Vercel accepts the deployment, but it does not wait for the remote build to finish. The command can therefore succeed even if that build later fails. Check the run's status in the dashboard, or poll it via the API with the printed run id.

## Custom domains

Add domains in the dashboard's Domains tab. After adding one, the tab shows the DNS records to create and re-checks verification automatically until they're live. Domains are managed in the dashboard (not in the config file), so they work the same no matter where your configuration comes from.
