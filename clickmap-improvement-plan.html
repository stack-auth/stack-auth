Turn up the heat.

What to protect: our one-event-carries-everything capture design. PostHog splits identity (autocapture) from coordinates ($$heatmap) from dead clicks (a separate lazy event stream) and reconciles them downstream. We capture identity + coordinates atomically per click — every improvement below should extend that single enriched row, never add parallel streams.
02
Reconnaissance

How PostHog actually does it

Condensed from posthog-js heatmaps + dead-clicks entrypoints and the PostHog ClickHouse pipeline.

Capture — posthog-js

  • Heatmaps class buffers points per URL, flushes a $$heatmap event every 5s + on beforeunload
  • Types: click, rageclick (3 clicks / 1s / 30px), deadclick, sampled mousemove
  • Dead clicks: lazy-loaded detector — MutationObserver + capture-phase scroll + selectionchange + visibilitychange; alive if scroll/selection ≤100ms or mutation ≤2500ms; dead at 2750ms; navigation implicitly = alive
  • Scroll depth rides on the next pageview/pageleave as $prev_pageview_max_scroll
  • Coords get scrollX/Y added unless target is fixed/sticky (target_fixed)

Backend + UX — posthog

  • plugin-server extractHeatmapData scales x/y/viewport by 16 → CH heatmaps table ordered (type, team_id, date, current_url, viewport_width)
  • API: type, date range, url_exact/url_pattern, scaled viewport min/max, total_count vs unique_visitors; scrolldepth bucketed to 100px
  • In-app HeatmapScene: sandboxed iframe of the user's site; screenshot fallback when X-Frame-Options blocks; screenshots generated from session replay
  • heatmap.js canvas gradient + element count labels + scrollmap fold line; toolbar mirrors it on the live site

The Plan

Four phases, cold to hot

Sizes: S ≤2 days · M ≤1 week · L 1–3 weeks. Canonical SDK source is packages/template/src/clickmap/ + the event tracker (synced into packages/js / packages/next). Phase hues follow getClickmapHue() — 185 down to 30, cold to hot.

P0

Quick wins — ship from data we already have

hue(185)

No schema changes, no new capture. Everything here is unlocked by existing ClickHouse rows.

Coordinate aggregation endpoint
We store pointer_x/pointer_y (scaled /16) on every row but the query engine only groups by route/selector/element. Add kind: "coordinates" to analytics-clickmap-query.ts: GROUP BY pointer_x, pointer_y (+ pointer_target_fixed split, client_y variant for fixed elements) returning {x, y, count}. Prerequisite for gradient heat in P2.
S
Replay deep-links from the overlay
session_replay_id is on every click row and the admin endpoint already returns per-replay aggregates. Add "watch replays of this click" on each element row → links into session replay filtered to that element's clicks. PostHog parity with near-zero backend work.
S
Unique-users toggle per element
Add uniqExact(user_id) to the elements aggregation and a clicks / users toggle in the overlay. Matches PostHog's total_count vs unique_visitors.
S
CSV/JSON export + share state
Export the element table; encode overlay filter state (range, pattern, device) into the sessionStorage payload so a reload restores the exact view.
S
CTR per element
We already ingest $page-view. Join clicks ÷ pageviews of the matching path to show "X% of visitors to this page clicked this" — PostHog's toolbar shows raw counts and rank percentages, not true view-based CTR.

P1

Signal parity — rage, dead, scroll (done better)

hue(140)

Match PostHog's signal family, but keep our single-enriched-row model: flags and measurements on the $click event instead of separate event streams that need reconciliation.

Annotate-in-place click pipeline
In the event tracker, hold each $click in a pending buffer for up to ~3s before enqueueing to the batch (flush interval is 10s, so latency cost is nil). During the hold, run the effect detector below and stamp the result onto the event. On pagehide, flush pending clicks immediately as alive-by-navigation.
M
Dead-click + interaction-latency detector
One document-level MutationObserver (subtree, attrs, childList, charData) + capture-phase scroll + selectionchange + visibilitychange. PostHog thresholds as defaults: scroll/selection ≤100ms = alive, mutation ≤2500ms = alive, dead at 2750ms. But record more than a boolean: stamp effect_delay_ms (click → first qualifying effect). That number is the raw material for the latency map in P3 — PostHog throws it away. Add data-hexclave-effect="none" opt-out for clipboard/audio/network-only elements (their known false-positive class).
M
Rage-click detection
Rolling window in the click handler: ≥3 clicks within 1s inside a 30px radius → stamp is_rage: 1 on the clicks in the burst (plus burst_size). No separate event type. Try it on this page, by the way.
S
Scroll-depth capture — reach AND attention
New $scroll event emitted at pageview end (route change / pagehide): max_scroll_y_scaled, doc height, viewport, and a compact dwell histogram — ms spent per 10%-of-page band. PostHog only captures max depth (reach); dwell-per-band gives us Clarity-style attention maps they don't have.
M
Backend: extend schema + MV
Add to $click enum/columns: is_rage UInt8, is_dead UInt8, effect_delay_ms Nullable(UInt16), pointer_type LowCardinality, click_index UInt16. New $scroll event type + scrollmap_events MV ordered like clickmap_events. Add scrolldepth + interaction-type filters to the query engine (interaction: "all" | "rage" | "dead").
M
Overlay: signal toggles + scrollmap view
Toolbar chips: All / Rage / Dead. Dead-click badges in red with dead-rate percentage per element ("18% of clicks here do nothing"). Scrollmap mode: horizontal reach gradient + average-fold line + per-band reach %, rendered from the $scroll aggregation.
M
P2

The viewing experience — kill the console paste

hue(58)

This is where PostHog beats us most and where users feel it most. Three escalating viewing modes, all launched with one click from the dashboard.

URL-fragment token handoff (replaces the snippet)
Dashboard "Open clickmap" opens https://site.com/#hexclave-clickmap-token=<JWT>. The SDK reads the fragment on boot, moves the token to sessionStorage, and strips the fragment via history.replaceState — fragments never reach servers or logs, and the existing origin-bound 24h JWT model is unchanged. The console snippet stays only as a documented fallback. This single change removes our worst UX step — consider pulling it into P0.
S
In-dashboard iframe viewer + postMessage bridge
New dashboard view embedding the site in a sandboxed iframe (token passed via fragment). A small bridge protocol (hexclave:clickmap:* messages, origin-checked both ways) lets the dashboard own the filter panel — date range, device, pattern, signal toggles, element list — while the overlay inside the iframe renders markers/heat only. Filters in dashboard chrome instead of floating on the page beats PostHog's toolbar-in-iframe approach.
L
Screenshot fallback from session replay
When X-Frame-Options/CSP blocks the iframe: reconstruct a static page image from our newest session replay snapshot matching the URL pattern + viewport bucket (auto-picked, with a manual picker), render it in the dashboard, and overlay coordinate heat + element badges on top. PostHog does this manually from a recording; auto-selection makes ours zero-config.
L
Canvas gradient heat layer
Render the P0 coordinate aggregation as a real heat gradient: ~100 lines — additive-alpha radial blobs on an offscreen canvas, then a palette LUT pass. No heatmap.js dependency. (The hero of this very page is that exact technique.) Modes: element badges / gradient / both; fixed-position points rendered viewport-anchored (client_y), scrolling points page-anchored — same split PostHog handles with target_fixed.
M
Dashboard landing page becomes a real page
Replace the token-launcher list with: per-origin preview cards, top pages by clicks, top elements site-wide, rage/dead hotspot counts for the selected range — each card opens the viewer pre-filtered.
M
P3

Beyond PostHog — things nobody ships

hue(30)

Built on effect_delay_ms, click_index, dwell bands, and our replay linkage — data PostHog either discards or never captures.

Interaction latency map
p50/p75/p95 of effect_delay_ms per element, painted as a slowness gradient. "This button works, but takes 1.8s to do anything visible" — INP-adjacent, per-element, from real users. PostHog's detector computes this delay internally and throws it away; no heatmap product surfaces it.
M
Error clicks
Capture-side: window.onerror / unhandledrejection within 1s of a click stamps had_error: 1. A dead click tells you nothing happened; an error click tells you why. Distinct toggle + color in the overlay.
S
First-click map + hesitation
click_index (added in P1) filtered to 1 = what users do first on each page. Hesitation: ms of hover dwell on the target before the click (pointerenter → click) — high hesitation + high dead-rate = confusing UI, a signal combo no competitor has.
M
Attention map
Render the P1 dwell-per-band histograms as a time-weighted scrollmap: not "how far did they get" but "where did they stay". Clarity-class feature, beyond PostHog entirely.
M
Compare mode + weekly hotspot digest
Side-by-side or delta overlay of two date ranges / device classes ("did the redesign move clicks?"). Plus a scheduled digest: top dead/rage/error hotspots week-over-week, deep-linking into the pre-filtered viewer. Turns the clickmap from a tool you remember to open into a product that tells you things.
L
∥

Hardening track — scale, privacy, correctness

parallel

Runs alongside the phases; none of it blocks features, all of it blocks growth if skipped.

Hourly rollups
SummingMergeTree keyed by (project, branch, hour, path, viewport_bucket, cityHash64(elements_chain), interaction_type). Long-range queries hit rollups; raw rows only for short ranges, coordinates, and replay drill-ins. Fixes the full-scan risk on 90-day queries.
M
Retention + PII guard
Per-project retention via CH TTL (default ~12 months). Capture-side masking: never record text from input/textarea/[type=password]/data-hexclave-mask subtrees; query-param allowlist on captured URLs (strip by default). PostHog's masking is opt-in; ours should be safe-by-default.
M
Ingest dedup + input metadata
Drop replayed batches by batch_id (retries currently double-count). Capture pointerType (mouse/touch/pen), devicePixelRatio, and keyboard activations (Enter/Space on focused element — clicks with no coordinates, currently invisible to every heatmap product).
S
Sampling correctness
Today unique counts are exact while click counts are upscaled — at low sampling rates "users > clicks" is possible. Either upscale uniques with HLL or annotate sampled responses so the UI labels estimates.

05
Failure Modes

Risks & design notes

R1
Dead-click false positives — clicks whose only effect is network/clipboard/audio look dead. Mitigations: the data-hexclave-effect opt-out, and (beyond PostHog) optionally counting fetch/XHR activity within the window as alive.
R2
Pending-buffer loss — holding clicks ≤3s risks losing the tail on hard tab kills. pagehide flush covers navigation; accept the residual loss like PostHog does, or mirror pending clicks to sessionStorage.
R3
Element drift — chains break when the DOM changes across deploys. Our 5-stage matcher degrades gracefully; surface an "unmatched clicks" count in the overlay instead of dropping silently.
R4
Iframe embedding will fail often — many production sites send X-Frame-Options. That's why fragment-handoff (works always) ships before the iframe viewer, and the screenshot path is a first-class mode, not an apology.
R5
Regex filter cost — user regex runs per-row at query time. Rollups bound the damage; keep regex on raw-row paths only and prefer glob in the UI.
R6
Quota growth — $scroll (1/pageview) is cheap; mousemove sampling is the expensive one, which is why it's deliberately excluded until there's a proven need.
Sequencing summary: P0 is days of work and makes the existing tool feel finished. P1 reaches signal parity with a structurally better data model. P2 removes the only part of our flow that's embarrassing next to PostHog. P3 is the moat — latency maps, error clicks, hesitation, attention — all derived from data we'll already be capturing by then.
